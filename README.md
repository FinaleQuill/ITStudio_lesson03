# 我的图书数据库作业

## 环境
- MySQL 版本：26.10.0。
- 本地安装 / Docker：Windows 本地安装，使用 MySQL Workbench 连接。
- 数据库名称：`lesson3_bookshop`，字符集为 `utf8mb4`。
- 连接方式：主机 `127.0.0.1`，端口 `3306`，用户 `root`，连接时输入密码。

## 从空库复现
1. 在 Workbench 连接本机 MySQL，打开 `sql/schema.sql` 并执行，创建数据库及两张表。
2. 打开并执行 `sql/seed.sql`，插入 4 位作者和 8 本书。价格、库存是练习数据。
3. 打开 `sql/queries.sql`，按 Q1 到 Q6 的顺序执行并核对结果。Q5、Q6 先执行查询确认目标，再执行修改和复查。

以上步骤从空库执行一次。Q5 会实际扣减库存，重复执行会继续扣减。重新从头练习时，将三个文件中的库名统一换成一个新的专用库名，再按顺序执行。

## 设计解释
- 主键为什么存在：`id` 给每条记录一个不重复的编号。作者可能同名，不能只靠名字区分。
- 外键引用哪张表的哪一列：`books.author_id` 引用 `authors.id`，表示这本书的作者。先有作者才能插入对应的书，一位作者可以对应多本书。
- 价格为什么选择这个类型：`DECIMAL(8,2)` 可以准确保存两位小数，适合记录价格。

## 六道题的预期结果
| 题号 | 预期结果 / 行数 | 验证方式 |
|---|---|---|
| Q1 | 茶馆、繁星，共 2 行，库存都是 0。 | 查看书名和 stock。 |
| Q2 | 受戒 52.00、荷塘月色 40.00、繁星 40.00，共 3 行。 | 价格从高到低，同价时 id 从小到大。 |
| Q3 | 茶馆、人间草木、骆驼祥子、荷塘月色、繁星、春水，共 6 行。 | 检查价格均在 20 到 40 之间，且包含两个边界。 |
| Q4 | 共 8 行，每本书都显示作者名和价格。 | 对照 authors 中的作者编号与姓名。 |
| Q5 | 骆驼祥子的库存从 6 变成 5。 | 比较 UPDATE 前后两次 SELECT 的结果。 |
| Q6 | 插入后 1 行，删除后 0 行。 | 用编号 1001 和完整的临时书名查询，确认没有误删原有的书。 |

## 排错或边界验证
- 现象：查询价格在 20 到 40 之间的书时，茶馆的 20.00 和三本书的 40.00 都出现在结果里。
- 原因：`BETWEEN 20 AND 40` 包含两端，不只是大于 20、小于 40。
- 处理与复验：核对 Q3 的 6 行结果，确认包含 20.00、40.00，不包含背影的 18.00 和受戒的 52.00。
